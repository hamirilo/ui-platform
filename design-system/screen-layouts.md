# Screen Layouts — 画面の起点レイアウト

新規画面・アプリは、原則として次の 3 つのいずれかを起点にする。
これらは実装コードをコピーする Template ではなく、ナビゲーションや主要操作位置を
揃えるための Layout Profile。

実物は Storybook「テンプレート/標準アプリ」「テンプレート/シンプルアプリ」「テンプレート/フォーカスアプリ」
（[templates/README.md](../templates/README.md)）。一覧・詳細・エラーページの構成例も同じ区分にある。

## Standard App — 一般的な業務システム、管理画面、マスタ管理

```
+--------------------------------------------------------------+
| Global Header: [アプリ/ブランド]              [User Menu]     |
+----------+---------------------------------------------------+
| Sidebar  | Page Header: [ページ名]          [Primary Action] |
| (主要ナビ) +---------------------------------------------------+
|          | Main Content                                      |
|          |                                                   |
+----------+---------------------------------------------------+
```

- Global Header を上部に。左にアプリ / ブランド、右に User Menu
- アプリ内の主要ナビゲーションは左 Sidebar
- Main Content 上部に Page Header、Primary Action は原則 Page Header 領域（右側）

## Simple App — 単機能ツール、小規模ユーティリティ、簡易申請

```
+--------------------------------------------------------------+
| Header: [アプリ名]                            [User Menu]     |
+--------------------------------------------------------------+
| (必要なら Page Header)                                        |
| Main Content（中心に構成）                                    |
+--------------------------------------------------------------+
```

- Sidebar を持たない
- 必要な場合のみ Main Content 上部に一貫した Page Header を置く

## Focus / Tool App — 座席表、エディタ、キャンバス型ツール

```
+--------------------------------------------------------------+
| Minimal Header: [アプリ名] [主要操作/Toolbar]  [User Menu]    |
+--------------------------------------------------------------+
| Main Workspace（残り全部を広く使う）                          |
+--------------------------------------------------------------+
```

- 主要操作は Header または一貫した Toolbar に集約する
- ユーザー関連操作の位置をアプリごとに無秩序に変えない

## 固定するもの / 拡張してよいもの

**強く揃える:** Header の基本位置、User Menu の位置、Standard App の Sidebar の役割と位置、
Page Header の役割、Primary Action の基本配置。

**アプリ要件で変えてよい:** Content 幅、Grid の列構成、Filter Bar・Tabs・Toolbar、
補助 Panel / Inspector、Dashboard Widget や情報密度。

3 レイアウトで足りない場合も、まず最も近いレイアウトを拡張する。

どのレイアウトでも、Main Content の中のまとまりは見出しと余白で作り、カードは「もの」を並べるときだけ使う
（[README §1「面の階層と強調」](README.md)、[ADR-0009](../decisions/adr-0009-surface-hierarchy-and-emphasis.md)）。
