# Django 連携（Islands）

Django テンプレート + htmx のアプリから、このキットの UI を**テンプレート側の記述だけ**で
使うための仕組みです。`data-react` 属性を持つ要素に React コンポーネントを自動マウントします。

React コンポーネントとして直接使う場合（`.tsx` の中）はこのページは不要です。
各 Component の Story を参照してください。

## 使い方

アプリの Vite エントリで auto-mount を import します。実際の GitHub Packages の scope は
利用側 `package.json` の npm alias が吸収するため、アプリコードでは常に `application-ui-kit` を使います。

<Code>{`// islands/main.ts
import 'application-ui-kit/islands/auto-mount'`}</Code>

これだけで、ページ内の `data-react` 要素（htmx スワップで後から入ったものも含む）が
自動でマウントされます。**htmx は entry より前に読み込みます**（auto-mount は読み込み時に
`window.htmx` を見て `htmx:afterSwap` の再スキャンを付けるため）。

自前の registry を持つアプリは、`application-ui-kit/islands` から Island を import して
自分の registry に登録します（default export が要る場合は 1 行のラッパーを書く）。

## テンプレート例

<Code>{`<!-- base.html に一度だけ（全ページトースト・確認の窓口） -->
<div data-react="toast-listener"></div>
<div data-react="confirm-host" data-intercept-hx-confirm="true"></div>

<!-- hx-confirm がそのまま kit のダイアログになる -->
<button hx-delete="/ideas/15/" hx-confirm="このアイデアを削除しますか？"
        data-confirm-title="アイデアの削除" data-confirm-text="削除">削除</button>

<!-- 既存の confirm-modal イベントもそのまま受かる -->
<button @click="$dispatch('confirm-modal', {title: '削除', message: '取り消せません。',
        confirmText: '削除', confirmClass: 'danger',
        onConfirm: () => document.getElementById('delete-form').submit()})">削除</button>

<!-- タブ（パネルはサーバーが描く） -->
<div data-tab-host>
  <div data-react="tabs" data-props='{"initial": "materials", "label": "コースの設定"}'></div>
  <section data-tab-panel="basic" data-tab-label="基本情報">…</section>
  <section data-tab-panel="materials" data-tab-label="教材"
           data-tab-count-id="material-count" hidden>…</section>
</div>

<!-- 入力欄の出し分け -->
<form>
  <span data-react="field-visibility" hidden></span>
  {{ form.kind }}
  <div data-visible-when='{"kind": ["video", "pdf"]}'>{{ form.url }}</div>
</form>

<!-- ファイル添付 -->
{{ form.attachment }}
<div data-react="file-drop-zone" data-target="{{ form.attachment.id_for_label }}"
     data-max-size="10485760" data-description="PDF のみ。10MB まで"></div>

<!-- 日付選択 -->
{{ form.start_date }}
<div data-react="date-picker" data-mode="single"
     data-target="{{ form.start_date.id_for_label }}"></div>`}</Code>

## 通知の流れ

- Django View: `messages.success(request, "保存しました")` → `data-messages` 経由でページ読込時にトースト表示
- 素の JS / htmx: `window.ApplicationToast.success("保存しました")`
- htmx の部分更新の結果: サーバーが `HX-Trigger: {"application-toast": {"type": "success", "title": "保存しました"}}` を返す
- form-dialog の送信成功: Django View が `HX-Trigger: application-form-success` を返す
- React マウント前の呼び出し: base.html のスタブが `window.__applicationToastQueue.push(["success", "…"])` しておけば、マウント時に消化される

## 注意事項

- 表示領域（Toaster）を持つのは toast-listener だけです。成功トーストを使う Island がある
  ページには toast-listener が必要です（通常は base.html に置くので満たされます）。
- confirm-host は 1 ページに 1 つ。2 つ目は警告を出して何もしません
  （複数が `htmx:confirm` を握ると 1 回の削除が複数回飛ぶため）。
  自前で `htmx:confirm` を握っているアプリは、そのリスナーを外してから `data-intercept-hx-confirm` を付けます。
- CSRF cookie 名を変更しているプロジェクトは `data-csrf-cookie-name` を渡してください
  （既定は Django 標準の `csrftoken`）。エンドポイントや認証方式は焼き込みません。
- 見せ方だけの島は、パネル・対象要素を差し替える htmx スワップの後も動きます（tabs は
  `htmx:afterSettle` でパネル集合と件数を読み直す）。Island 自身の要素が差し替わった場合は再マウントされます。
- 業務ドメイン固有の Island はこのパッケージに追加せず、アプリ側で
  `registerIslandComponents()` を使って登録します。
- `data-props` に Django の値を渡すときは、文字列連結で JSON を組み立てず
  `json_script` 等の安全なシリアライズ手段を使ってください。

詳細な設計判断は リポジトリの `decisions/adr-0001-django-htmx-islands.md` と
`decisions/adr-0007-template-class-contract-and-presentation-islands.md` を参照してください。
